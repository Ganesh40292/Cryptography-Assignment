⊕ ARX Design — The Quarter Round
RFC 8439 §2.1
ADD a + b mod 2³² XOR d ⊕ a ROTATE ⟲ 16 · 12 · 8 · 7 = ARX

Each quarter round transforms four 32-bit words with three constant-time operations only — no tables, no branches — which is what makes ChaCha20 fast and cache-timing resistant.

  1. a += b— word a absorbs b (addition mod 2³²)
  2. d ^= a · d <<<= 16— d mixes with a, then rotates left 16
  3. c += d— word c absorbs d
  4. b ^= c · b <<<= 12— b mixes with c, rotates left 12
  5. a += b— word a absorbs b again
  6. d ^= a · d <<<= 8— d mixes with a, rotates left 8
  7. c += d— word c absorbs d again
  8. b ^= c · b <<<= 7— b mixes with c, rotates left 7
Column round QR(0,4,8,12) QR(1,5,9,13) QR(2,6,10,14) QR(3,7,11,15)
Diagonal round QR(0,5,10,15) QR(1,6,11,12) QR(2,7,8,13) QR(3,4,9,14)

10 column rounds + 10 diagonal rounds = 20 rounds · 80 quarter-round calls per 64-byte block

⇣ How ChaCha20 Works — Encryption Pipeline
STREAM CIPHER · XOR SYMMETRIC
  1. 256-BIT KEY

    A 32-byte secret shared by sender & receiver; this studio generates it or accepts 64 hex characters.

  2. ↓
  3. INITIAL STATE

    16-word matrix: constants “expand 32-byte k”, 8 key words, block counter, 3-word nonce.

  4. ↓
  5. 20 ROUNDS

    10 double rounds — each applies 4 column quarter-rounds then 4 diagonal quarter-rounds to the state.

  6. ↓
  7. ARX OPERATIONS

    Only addition mod 2³², XOR and fixed left rotations (16, 12, 8, 7) — see the quarter-round panel.

  8. ↓
  9. FEED-FORWARD

    The permuted state is added to the original state (mod 2³²) so the round function is invertible.

  10. ↓
  11. KEYSTREAM

    The 16 output words are serialized little-endian into a 64-byte pseudo-random keystream block.

  12. ↓
  13. XOR

    Keystream ⊕ plaintext: C = P ⊕ K. Because XOR is self-inverting, decryption uses the identical keystream.

  14. ↓
  15. CIPHERTEXT

    Same length as the plaintext; messages > 64 bytes simply advance the block counter per block.
