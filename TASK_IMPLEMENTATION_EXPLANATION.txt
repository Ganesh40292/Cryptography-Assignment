2. CRYPTOGRAPHIC ANALYSIS OF CHACHA20 & RFC 8439
================================================================================

2.1 DESIGN RATIONALE & HISTORY
------------------------------
Designed by Daniel J. Bernstein in 2008 as an evolution of Salsa20, ChaCha20 was 
standardized by the IETF in RFC 7539 and refined in RFC 8439. It is widely adopted 
in TLS 1.3, OpenSSH, WireGuard VPN, and Android OS as the premier high-speed 
software alternative to AES.

2.2 ARX ARCHITECTURE & CACHE-TIMING IMMUNITY
--------------------------------------------
Unlike block ciphers such as AES or DES that rely on secret-dependent Substitution 
Boxes (S-Boxes) stored in lookup tables:
* ChaCha20 relies exclusively on ARX operations:
  - (A) Addition modulo 2^32:      a = (a + b) mod 2^32
  - (R) Bitwise Circular Rotation: d = (d ^ a) <<< rot
  - (X) Bitwise XOR:               d = d ^ a
* TIMING ATTACK RESISTANCE: Every ARX operation executes in constant instruction 
  cycles on modern CPUs, eliminating cache-timing side-channel vulnerabilities.

2.3 512-BIT STATE MATRIX COMPOSITION
-------------------------------------
The internal state comprises sixteen 32-bit unsigned integers arranged in a 4x4 
matrix (total 64 bytes / 512 bits):

   +--------------------+--------------------+--------------------+--------------------+
   | [0] Constant C0    | [1] Constant C1    | [2] Constant C2    | [3] Constant C3    |
   | 0x61707865 ("expa")| 0x3320646e ("nd 3")| 0x79622d32 ("2-by")| 0x6b206574 ("te k")|
   +--------------------+--------------------+--------------------+--------------------+
   | [4] Key Word K0    | [5] Key Word K1    | [6] Key Word K2    | [7] Key Word K3    |
   +--------------------+--------------------+--------------------+--------------------+
   | [8] Key Word K4    | [9] Key Word K5    | [10] Key Word K6   | [11] Key Word K7   |
   +--------------------+--------------------+--------------------+--------------------+
   | [12] Counter CTR   | [13] Nonce N0      | [14] Nonce N1      | [15] Nonce N2      |
   +--------------------+--------------------+--------------------+--------------------+

* Words 0–3:   Fixed constant "expand 32-byte k" (prevents all-zero states).
* Words 4–11:  Eight 32-bit words of the 256-bit secret key (little-endian).
* Word 12:     32-bit block counter (increments per 64-byte keystream block).
* Words 13–15: Three 32-bit words of the 96-bit unique nonce.

2.4 THE QUARTER-ROUND FUNCTION (QR)
-----------------------------------
The fundamental cryptographic primitive is QR(a, b, c, d), operating on four 
words of the matrix through 4 cyclic ARX rounds:

   1. a = (a + b) mod 2^32;  d = (d ^ a) <<< 16;
   2. c = (c + d) mod 2^32;  b = (b ^ c) <<< 12;
   3. a = (a + b) mod 2^32;  d = (d ^ a) <<< 8;
   4. c = (c + d) mod 2^32;  b = (b ^ c) <<< 7;

Each Quarter-Round provides complete diffusion across all 4 target words.

2.5 20-ROUND PERMUTATION CYCLE
------------------------------
ChaCha20 executes 10 double-rounds (total 20 rounds), alternating between:
* COLUMN ROUNDS (Odd Rounds 1, 3, 5, ..., 19):
  - QR(0, 4,  8, 12)  [Column 0]
  - QR(1, 5,  9, 13)  [Column 1]
  - QR(2, 6, 10, 14)  [Column 2]
  - QR(3, 7, 11, 15)  [Column 3]

* DIAGONAL ROUNDS (Even Rounds 2, 4, 6, ..., 20):
  - QR(0, 5, 10, 15)  [Main Diagonal]
  - QR(1, 6, 11, 12)  [Diagonal + 1]
  - QR(2, 7,  8, 13)  [Diagonal + 2]
  - QR(3, 4,  9, 14)  [Diagonal + 3]

Alternating between columns and diagonals ensures that every single bit in the 
state matrix diffuses to every other bit within 4 rounds.

2.6 FEED-FORWARD ADDITION & KEYSTREAM GENERATION
------------------------------------------------
After 20 rounds of permutation, the original initial state is added to the 
permuted working state modulo 2^32:
   KeystreamWord[i] = (PermutedState[i] + InitialState[i]) mod 2^32

This feed-forward operation makes the round function non-invertible.
The resulting sixteen 32-bit words are serialized in little-endian order into a 
64-byte keystream block. The plaintext is then XORed with the keystream:
   Ciphertext = Plaintext ^ Keystream

2.7 POLY1305 ONE-TIME MAC & AEAD CONSTRUCTION (§2.8)
-----------------------------------------------------
ChaCha20-Poly1305 AEAD provides Authenticated Encryption with Associated Data:
1. Subkey Generation: Evaluates block counter 0 to derive a 256-bit one-time 
   Poly1305 key (r, s).
2. Encryption: Encrypts plaintext using ChaCha20 starting at block counter 1.
3. Authenticator: Computes a 16-byte Poly1305 MAC tag modulo 2^130 - 5 over:
   AAD || Pad16(AAD) || Ciphertext || Pad16(Ciphertext) || len(AAD) || len(Ciphertext)
4. Verification: The receiver verifies the tag before decrypting or releasing 
   any plaintext, preventing chosen-ciphertext and tampering attacks.

3. SUITABLE PROGRAMMING APPROACH & SYSTEM ARCHITECTURE
================================================================================

3.1 ZERO-DEPENDENCY PURE JAVA 17+ CORE
--------------------------------------
The backend engine is implemented in standard Java 17+ with zero third-party 
libraries. All bitwise operations use primitive integer types (`int`, `long`) 
and explicit 32-bit unsigned masks (`& 0xFFFFFFFFL`).

3.2 ARCHITECTURAL DECOMPOSITION (CLASS BREAKDOWN)
------------------------------------------------
The source code under `com.chacha20` is organized into cohesive classes:

1. ChaCha20.java:
   - Core mathematical engine implementing RFC 8439 §2.1–§2.4.
   - Bitwise ARX Quarter-Round, Block Function, and keystream serialization.
   - Supports configurable round variations: ChaCha8, ChaCha12, and ChaCha20.
   - Little-endian byte/word packing and unpacking utilities.

2. Poly1305.java:
   - RFC 8439 §2.5 implementation of the 128-bit Poly1305 authenticator.
   - Modular arithmetic modulo 2^130 - 5.
   - Constant-time tag comparison (`MessageDigest.isEqual`) to eliminate timing leaks.

3. ChaCha20Poly1305.java:
   - RFC 8439 §2.8 AEAD construction.
   - Generates one-time subkeys via ChaCha20 counter 0.
   - Enforces authentication before decryption (reject-on-tamper guarantee).

4. FileCipher.java:
   - Buffered streaming file cipher operating in fixed 64 KB memory buffers.
   - Capable of streaming gigabyte-scale files with constant RAM consumption.
   - Includes realpath resolution to prevent same-path file overwrite/truncation.

5. AvalancheAnalyzer.java:
   - Empirical statistical analysis of the Avalanche Effect (bit-diffusion).
   - Flips single bits in key, nonce, or counter and measures hamming distance.
   - Multi-trial statistical reporting (mean, min, max, std-dev).

6. BenchmarkRunner.java:
   - Academic performance measurement across multiple payload sizes (64 B to 1 MB).
   - Measures raw encryption throughput (MB/s) and per-block latency (microseconds).
   - Evaluates performance scaling between ChaCha8, ChaCha12, and ChaCha20.

7. StateTracer.java:
   - Formatted ASCII visualizer displaying the 4x4 matrix across round transitions.

8. HexUtils.java & InputValidator.java:
   - Strict cryptographic input sanitization, hex encoding/decoding, and length checks.

9. Main.java:
   - Interactive 10-option CLI menu for demonstration, testing, and file operations.

3.3 CONSTANT-MEMORY 64 KB FILE STREAMING ENGINE
-----------------------------------------------
The `FileCipher` class streams files through 64 KB buffers while incrementing the 
block counter by `bytesRead / 64`. This architecture enables encrypting large 
binary files (PDFs, images, archives) without loading the entire file into RAM.
